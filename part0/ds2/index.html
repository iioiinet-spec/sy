1왜 필요한가

01장에서 “10만 × 10만 = 100억”을 손으로 셌다. 이 장은 그 셈을 모두가 쓰는 공통 언어로 바꾸는 작업이다.

1.1 같은 답, 다른 결과

두 학생이 목표 합이 되는 두 수를 찾는 문제를 풀었다고 가정하자. 둘 다 작은 예제에서 정답이 나왔고, 둘 다 자신 있게 제출했다. 그런데 한 명은 통과하고 한 명은 시간 초과를 받았다.

학생방법N = 100,000일 때결과
민수모든 두 수의 쌍을 전부 확인약 50억 쌍시간 초과 위험
지우먼저 정렬한 뒤 양 끝에서 좁혀 감약 170만 단계(어림)통과 가능

두 코드 모두 정답을 구한다. 차이는 오직 “몇 번 일하는가”에 있다. 대회에서는 맞는 답을 제한 시간 안에 내야 하므로, 코드를 돌려 보기 전에 몇 번 일하는지 셀 줄 알아야 한다. 그 세는 방법이 복잡도다.

1.2 왜 ‘초’가 아니라 ‘횟수’로 세는가

“내 노트북에서 0.5초 걸렸으니 괜찮겠지”는 위험한 판단이다. 시간은 CPU, 컴파일러, 입력 데이터에 따라 달라지고 채점 서버가 반드시 느린 것도 아니다. 반면 명시적으로 세는 비교·반복 횟수는 같은 입력과 알고리즘이면 일정하다.

이 장의 기준선 — 1초에 약 1억 번

초기 설계에서는 1초에 단순 작업 약 1억 번(108)을 매우 거친 참고값으로 사용한다. 단순 정수 연산·메모리 접근·함수 호출·입출력의 실제 비용은 크게 다르므로 이 숫자만으로 통과를 확정할 수 없다. 3.2절에서는 직접 측정해 차이를 확인한다.

1.3 두 가지 제한

대회 문제에는 항상 두 개의 상한이 붙는다. 둘 중 하나라도 초과하면 시간 초과나 메모리 초과 등으로 채점에 실패한다.

시간 제한 — 보통 1~2초

총 연산 횟수가 기준을 넘으면 시간 초과(TLE). 이 장의 1~4절이 다룬다.

메모리 제한 — 예시 256MiB

전체 메모리 사용량이 한도를 넘으면 메모리 초과(MLE) 또는 실행 오류가 날 수 있다. 4.3절에서 계산법을 익힌다.

자료구조를 배우는 내내 이 두 숫자가 따라다닌다. 세그먼트 트리가 배열을 4배로 잡는 이유(27장)도, 희소 테이블이 메모리를 O(N log N)이나 쓰는 이유(25장)도 전부 이 두 제한과의 흥정이다.

연산 횟수를 세고, 그 결과를 빅오로 줄이는 두 단계를 익힌다.

2.1 연산 횟수 세기 — 루프를 본다

반복문 중심의 기초 문제에서는 “핵심 작업이 총 몇 번 실행되는가”를 센다. 안에서 호출하는 함수의 비용도 포함해야 한다.

코드 모양실행 횟수복잡도세는 방법
x = a + b;1O(1)루프가 없으면 N과 무관하게 한 번
for (i=0; i<n; i++)NO(N)한 칸씩 끝까지 → N번
for(i=0;i<n;i++) for(j=0;j<n;j++)N × NO(N²)바깥 N번 × 안쪽 N번
for(i=0;i<n;i++) for(j=i+1;j<n;j++)N(N−1)/2O(N²)절반이어도 N²에 비례한다
while (n > 1) n /= 2;⌊log₂N⌋ (N≥1)O(log N)정수 나눗셈으로 반으로 줄이는 횟수
for(i=0;i<n;i++) for(k=n;k>1;k/=2)N × log₂NO(N log N)곱한다

log는 밑이 2다

복잡도 표기에서는 로그의 밑이 1보다 큰 상수라면 빅오가 같고, 이 교재는 계산 편의상 log₂를 쓴다. 외워 둘 값은 셋 — log₂ 1,000 ≈ 10, log₂ 100,000 ≈ 17, log₂ 1,000,000 ≈ 20.

2.2 빅오 표기 — 버릴 것을 버린다

연산 횟수를 세었더니 3N² + 5N + 100이었다고 하자. 빅오는 두 가지를 버린다.

  1. 최고차항만 남긴다 — 5N과 100을 버린다
  2. 계수를 버린다 — 3N²에서 3을 버린다 → O(N²)

왜 버려도 되는지는 숫자를 대입해 보면 바로 보인다.

N이 커질수록 나머지는 있으나 마나 해진다. 복잡도는 N이 충분히 커졌을 때 증가율의 상한을 보는 도구이므로 작은 항과 계수를 버려도 판단이 달라지지 않는다.

Q. 그러면 3배 차이는 무시해도 되나요? 3초와 1초는 큰 차이인데요.
경우에 따라 다르다. 복잡도가 다르면(N² vs N log N) 충분히 큰 N에서 차수가 중요하다. 그러나 실제 입력이 작을 때는 상수도 여전히 중요하다. 하지만 복잡도가 같은데 상수 비용이 다르면 그 차이가 통과와 초과를 가른다 (2.5절).

2.4 최악·평균·최선 — 최악부터 확인한다

배열에서 값을 선형 탐색할 때를 보자. 찾는 값의 위치에 따라 비교 횟수가 달라진다.

경우찾는 값의 위치비교 횟수대회에서의 취급
최선맨 앞1쓰지 않는다 — 운에 기대는 셈
평균(가정)존재하는 값이 각 위치에 균등할 때(N+1) / 2성공 탐색의 평균; 분포에 따라 달라짐
최악맨 뒤 또는 없음N이것으로 판정한다

채점 데이터에는 어려운 입력이 들어올 수 있으므로 최악 시간 복잡도를 먼저 확인하는 것이 안전하다. 다만 무작위 알고리즘이나 해시 테이블처럼 기대·평균 성능을 따로 분석하는 경우도 있다. 이 교재는 별도 표기가 없으면 최악 시간 복잡도를 다룬다.

2.5 계수를 버려도 될 때와 아닐 때

빅오는 계수를 버리지만 채점기는 계수까지 겪는다. 두 경우를 구분하자.

버려도 될 때 — 복잡도가 다르다

N = 100,000에서 N² = 100억과 N log₂N ≈ 166만의 단순 계산값은 약 6,000배 차이다. 실제 실행 시간의 배율과 같지는 않다.

버리면 안 될 때 — 복잡도가 같다

둘 다 O(N log N)인데 상수가 3배면 1.5초와 0.5초로 갈려 한쪽만 통과한다. 그때부터는 상수를 줄이는 싸움이다.

상수를 키우는 대표적 요인은 메모리를 멀리 떨어진 곳에서 읽는 것이다. 같은 O(N)이라도 배열을 차례로 읽으면 빠르고 흩어진 주소를 따라가면 몇 배 느리다.

3구현 — 추정을 검산하는 두 도구

3.1 연산 횟수 카운터

전역 변수 하나를 두고 핵심 연산이 일어나는 줄에서 1씩 올린다. 선형 탐색과 이분 탐색을 같은 입력에 돌려 보자.

/* counter.c — 연산 횟수를 직접 세어 복잡도를 확인한다 */
#include <stdio.h>
long long cnt;                      /* 전역 계수기 */
static int a[1000000];              /* 큰 배열은 전역에 */

int linear_search(const int *a, int n, int key){
    for (int i = 0; i < n; i++) {
        cnt++;                          /* 탐색 반복 1회(원소 확인 1회) */
        if (a[i] == key) return i;
    }
    return -1;
}
int binary_search(const int *a, int n, int key){
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        cnt++;                          /* 탐색 반복 1회(원소 확인 1회) */
        int mid = lo + (hi - lo) / 2;   /* 오버플로 예방형 */
        if (a[mid] == key) return mid;
        if (a[mid] < key) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}
int main(void){
    int n = 1000000, key = n - 1;       /* 선형 탐색의 최악, 이분 탐색의 한 사례 */
    for (int i = 0; i < n; i++) a[i] = i;
    cnt = 0; linear_search(a, n, key);
    printf("선형 탐색 원소 확인 횟수 : %lld\n", cnt);
    cnt = 0; binary_search(a, n, key);
    printf("이분 탐색 원소 확인 횟수 : %lld\n", cnt);
    return 0;
}

읽는 법

이 입력에서 선형 탐색은 정확히 N번, 이분 탐색은 20번의 원소 확인을 한다. 이는 log₂ 1,000,000 ≈ 19.93과 가까우나 일반적으로 정확히 같지는 않다. 이 형태의 이분 탐색에서 최대 원소 확인 횟수는 ⌊log₂N⌋ + 1 (N≥1)이다. 앞으로 카운터로 작업량을 검산하자.

3.2 실측 타이머

※ qsort는 C11 표준 정렬 함수지만 표준에서 최악 시간 복잡도를 약속하지 않는다. 아래 예제의 O(N log N)은 일반적인 효율적 정렬의 평균적·전형적 작업량을 뜻한다.

<time.h>의 clock()은 프로그램이 쓴 CPU 시간을 돌려준다. 시작과 끝에서 두 번 불러 차이를 CLOCKS_PER_SEC으로 나누면 초가 된다.

/* timer.c — 같은 N에서 세 복잡도의 시간을 재어 본다 */
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define N 50000
static int a[N];
static int cmp(const void *p, const void *q){
    int x = *(const int*)p, y = *(const int*)q;
    return (x > y) - (x < y);       /* 뺄셈 대신 — 오버플로 예방 */
}
int main(void){
    clock_t st;  unsigned long long guard = 0;
    for (int i = 0; i < N; i++) a[i] = rand();

    st = clock();                                  /* O(N) */
    for (int i = 0; i < N; i++) guard += a[i];
    printf("O(N)       합 구하기 : %8.1f ms\n",
           1000.0 * (clock() - st) / CLOCKS_PER_SEC);

    st = clock();                                  /* 평균적 O(N log N), 표준 qsort의 최악 복잡도는 보장되지 않음 */
    qsort(a, N, sizeof(int), cmp);
    printf("O(N log N) 정렬하기  : %8.1f ms\n",
           1000.0 * (clock() - st) / CLOCKS_PER_SEC);

    st = clock();                                  /* O(N^2) */
    for (int i = 0; i < N; i++)
        for (int j = i + 1; j < N; j++) guard += a[i] ^ a[j];
    printf("O(N^2)     모든 쌍   : %8.1f ms\n",
           1000.0 * (clock() - st) / CLOCKS_PER_SEC);

    printf("(검증용 누적값 %llu)\n", guard);
    return 0;
}
$ gcc -std=c11 -O2 -Wall -Wextra timer.c -o timer && ./timer
O(N)       합 구하기 :   약 0.0 ms
O(N log N) 정렬하기  :   약 4.5 ms
O(N^2)     모든 쌍   : 약 375.1 ms

관찰의미
O(N)이 0.0 ms표시를 소수점 한 자리 ms로 반올림해 0.0으로 보일 수 있다. clock()의 해상도는 환경마다 다르므로 “정확히 0초”가 아니라 “이 표시 자릿수로는 구분하기 어렵다”로 읽는다
정렬이 4.5 msN log₂N ≈ 78만은 정렬 작업량의 대략적 척도다. 비교 함수 호출과 데이터 분포에 따라 실제 비교·이동 횟수는 다르다
O(N²)이 375 ms정확히 N(N−1)/2 = 1,249,975,000쌍이다. 같은 환경에서 N을 2배로 늘리면 작업량은 약 4배지만 실행 시간의 배율은 일정하지 않다.

“1초에 1억”과 측정값이 다른 이유

예시의 12.5억 쌍과 0.375초를 단순히 나누면 초당 약 33억 쌍 처리로 보이지만, 이것이 모든 C 코드의 처리 속도라는 뜻은 아니다. 실제 측정에는 컴파일러 최적화·벡터화·캐시·CPU 성능이 영향을 준다. “1초에 1억 번”은 단위가 일정한 실제 연산 속도가 아니라 거친 설계용 감각이다. 가장 큰 입력으로 여러 번 실행해 확인한다.

※ 위 시간은 실제 측정의 보편적 결과가 아니라 설명용 예시 수치다. CPU, 컴파일 옵션, 난수 데이터, 최적화 및 반복 횟수에 따라 배율까지 달라질 수 있다. 직접 실행한 수치를 별도로 기록하자.

4복잡도 분석 — 제약 조건에서 거꾸로 읽기

실전에서 복잡도를 쓰는 방식은 “내 코드가 몇 인가”가 아니라 “무엇까지 허용되는가”를 먼저 정하는 것이다.

4.1 N을 보고 복잡도를 고르는 표

문제의 제약 조건에서 N의 최댓값을 확인한 뒤, 이 표에서 우선 검토할 복잡도 후보를 읽는다. 시간 제한 1초 기준으로 아주 거친 설계 참고표다. 실제 통과 여부는 연산 내용과 채점 환경에 따라 다르다.

N의 최댓값허용 복잡도총 연산 횟수대표적인 풀이 방법
N ≤ 10O(N!)360만모든 순열을 만들어 보기
N ≤ 20~25O(2N)100만~3천만부분집합 전부 확인, 비트마스크
N ≤ 500O(N³)1억 2천5백만삼중 루프, 플로이드 워셜 (상수 비용 확인)
N ≤ 5,000O(N²)2천 5백만이중 루프, 기본 DP
N ≤ 100,000O(N log N)약 170만정렬, 이분 탐색, 세그먼트 트리
N ≤ 1,000,000O(N log N)약 2천만정렬, 우선순위 큐
N ≤ 10,000,000O(N)1천만한 번 훑기, 누적 합, 투 포인터

거꾸로 읽는 훈련이 핵심이다

N ≤ 100,000이라는 조건을 보면 “N log N 정도의 풀이를 우선 찾아야겠구나”가 먼저 떠올라야 한다. 그러면 풀이를 떠올리는 범위가 단숨에 좁혀진다. 이중 루프가 보이는 순간 “이건 아니다”라고 바로 접을 수 있다. 제약 조건은 출제자가 남긴 힌트다.

4.2 N²은 언제부터 포기하는가

실전 기준선 하나만 외우자. N이 1만을 넘으면 O(N²)은 먼저 의심한다. N = 10,000에서 N² = 1억, N = 100,000에서 100억이다. 단순한 연산의 상수가 작거나 루프가 일찍 끝나면 상황이 달라질 수 있지만, 보통은 더 빠른 접근을 먼저 찾는다.

4.3 공간 복잡도 — 배열이 메모리에 들어가는가

메모리 제한이 256MiB(= 268,435,456바이트)라고 하자. 다음 숫자는 int 4바이트, long long 8바이트인 일반적인 환경에서의 이론상 최대치다. 먼저 두 수의 감각을 익힌다.

자료형1개 크기256MiB에 들어가는 개수기억할 형태
int4 바이트약 6,700만 개int 배열은 6천만 개까지
long long8 바이트약 3,300만 개long long은 그 절반

실제로는 다른 배열·런타임 메모리도 포함되므로 여유를 둬야 한다. 무조건 절반만 쓸 필요는 없지만 한계에 가까우면 전체 사용량을 확인해야 한다. 자주 쓰는 크기를 미리 계산해 두면 선언할 때 망설이지 않는다.

선언원소 개수메모리판정
int a[1000000];100만약 3.8 MiB여유
long long a[1000000];100만약 7.6 MiB여유
int a[1000][1000];100만약 3.8 MiB여유
int a[2000][2000];400만약 15.3 MiB여유
int a[5000][5000];2,500만약 95.4 MiB주의
int a[100000][100000];100억약 37.3 GiB (40 GB)불가능

큰 지역 배열은 스택 한도를 확인한다

main 안에 int a[1000000];을 선언하면 약 3.8MiB가 필요하다. 지역 배열은 일반적으로 스택에 놓이므로 환경의 스택 한도에 따라 정상 실행되거나 실패할 수 있다. 크기가 큰 고정 배열은 함수 밖의 전역 또는 static 배열로 두는 편이 안전하다. 정적 저장 기간의 배열은 0으로 초기화된다.

5예제

예제 1 코드 보고 판정

다음 세 조각의 시간 복잡도를 각각 구하라. n은 입력 크기다.

(가) for(i=0;i<n;i++) for(j=0;j<n;j++) s += a[i]*a[j];

(나) for(long long i=1;i<=n;i*=2) s += i;

(다) for(i=0;i<n;i++) for(j=0;j<100;j++) s += a[i];

풀이.

  • (가) O(N²) — 바깥 N번, 안쪽 N번이 중첩되어 N × N번.
  • (나) O(log N) — i가 1, 2, 4, 8…로 2배씩 커지므로 n을 넘기까지 log₂n번 돈다. 반으로 줄이는 것과 2배로 늘리는 것은 같은 횟수다.
  • (다) O(N) — 안쪽이 100번이지만 n과 무관한 고정값이다. 총 100N번이고 계수 100을 버리면 O(N). 100번이라는 이유로 O(N²)이라고 답하면 틀린다.
예제 2 계수를 버리는 이유

A 알고리즘의 연산 횟수는 100N, B 알고리즘은 N²이다. (1) N이 얼마를 넘을 때부터 A가 유리해지는가? (2) N ≤ 1,000,000인 문제에서 어느 쪽을 골라야 하는가?

풀이. (1) 100N < N²을 풀면 N > 100. 즉 N이 100을 넘는 순간부터 A가 유리하다. N = 100에서는 둘 다 1만 번으로 같다.

NA : 100NB : N²유리한 쪽
101,000100B
10010,00010,000같음
1,000,0001억1012A (1만 배)

(2) 당연히 A. 상수 100이 아무리 커 보여도 N이 커지면 무의미해진다. 이것이 빅오가 계수를 버리는 이유다 — 우리가 궁금한 것은 언제나 N이 최대일 때이기 때문이다.

예제 3 제약 조건에서 역산

어떤 문제의 제약 조건이 “1 ≤ N ≤ 2,000, 시간 제한 1초”다. (1) 허용되는 복잡도의 상한은? (2) 삼중 루프 풀이를 떠올렸다면 제출해도 되는가?

풀이. (1) N = 2,000을 대입해 본다. 아래 판정은 단순 작업 횟수를 가정한 어림이다.

복잡도N = 2,000일 때판정
O(N log N)약 22,000여유
O(N²)400만통과
O(N² log N)약 4,400만아슬아슬하나 가능
O(N³)80억대체로 어려움 (80억 단계)

기본 후보는 O(N²) 정도이고, 작업이 매우 가벼우면 O(N² log N)도 검토할 수 있다. (2) 단순 삼중 루프는 80억 단계여서 시간 초과 가능성이 매우 높다. 코드를 쓰기 전에 이 계산을 하면 30분을 아낀다. N ≤ 2,000은 이중 루프 풀이를 우선 떠올리게 하는 단서다.

예제 4 메모리 계산

메모리 제한이 256MiB다. long long dp[5000][5000];을 선언해도 되는가? 안 된다면 어떻게 해야 하는가?

풀이. 원소 개수는 5,000 × 5,000 = 2,500만 개, 하나가 8바이트이므로 2억 바이트, 약 190.7MiB(200MB)다. 전역·정적 배열이라면 256MiB 제한 안에 들어가지만 여유가 크지는 않다. 함수 내부의 큰 지역 배열이라면 스택 한도로 실패할 위험이 높다.

대처 세 가지.

  • 자료형 줄이기 — 값의 범위가 20억 이하라면 int로 바꿔 약 95.4MiB로 절반이 된다
  • 줄을 줄이기 — DP에서 dp[i]를 구할 때 dp[i-1]만 필요하다면 두 줄짜리 dp[2][5000]로 바꿔 8만 바이트까지 줄일 수 있다 (슬라이딩 배열)
  • 안 만들기 — 실제로 쓰이는 칸이 전체의 일부뿐이라면 좌표 압축(23장)이나 해시(21장)로 필요한 만큼만 둔다

예제를 풀고 나서 — 몸에 붙여야 할 순서

① 제약 조건에서 N 확인 → ② 복잡도 후보 검토 → ③ 그 복잡도로 풀이 설계 → ④ 메모리 점검 → ⑤ 코딩. 많은 학생이 ⑤부터 시작했다가 다 짜고 나서 시간 초과를 받는다. ①~④는 합쳐서 1분이면 끝난다.

7도전 문제

답이 하나로 떨어지지 않는다. 근거를 갖춘 추정을 쓰는 것이 목표다.

C1출제자의 의도 읽기
같은 문제가 두 가지 버전으로 출제되었다. 문제의 내용은 완전히 같고 제약 조건만 다르다.
· 버전 A — N ≤ 1,000, 시간 제한 1초   ·   버전 B — N ≤ 500,000, 시간 제한 1초
(1) 각 버전에서 허용되는 복잡도의 상한을 구하라.
(2) 출제자가 같은 문제를 두 버전으로 낸 이유는 무엇이겠는가? 채점 결과가 어떻게 갈릴지 예상해 설명하라.
(3) 버전 A는 맞고 버전 B는 시간 초과가 났다면 어떤 복잡도를 후보로 의심할 수 있는가? 두 채점 결과만으로 정확한 빅오를 확정할 수 있는가?
C2복잡도가 거짓말을 할 때
두 프로그램이 모두 크기 N인 배열의 모든 원소를 한 번씩 더한다. 복잡도는 둘 다 O(N)이다.
· 프로그램 P — 배열을 앞에서부터 차례대로 a[0], a[1], a[2], … 읽는다
· 프로그램 Q — 같은 값들을 연결 리스트에 흩어 담아 두고 화살표를 따라가며 읽는다
(1) 두 프로그램의 시간 복잡도를 각각 쓰라.
(2) 실제로 재 보면 Q가 몇 배 느릴 수 있다. 빅오가 같은데 왜 시간이 다른지 2.5절을 근거로 설명하라.
(3) 이 사실이 자료구조를 고를 때 주는 교훈을 한 문장으로 쓰라.
(4) (선택) 3.2절의 타이머로 두 경우를 직접 만들어 재어 보고, 실제 배율을 보고하라.

도전 문제를 풀기 전에

C1은 실제 대회에서 자주 쓰이는 출제 방식이다. 같은 문제의 쉬운 버전과 어려운 버전을 나란히 내면, 느린 풀이를 떠올린 학생도 점수를 얻되 빠른 풀이를 찾아낸 학생과 구분된다. C2는 24장 누적 합부터 32장 트라이까지 계속 따라다니는 주제다. 복잡도는 가장 중요한 기준이지만 유일한 기준은 아니다.

8막히는 지점

흔한 생각무엇이 틀렸나바로잡기
“내 컴퓨터에서 빨랐으니 통과하겠지”채점 환경·컴파일러·테스트 데이터가 다르다작업량을 먼저 추정하고 실제 최댓값으로 검증한다. 1억은 참고값일 뿐이다
“루프가 두 개니까 무조건 O(N²)”안쪽이 상수 횟수면 O(N)이다. 반대로 루프 하나라도 안에서 함수를 부르면 더 클 수 있다중첩 모양이 아니라 핵심 작업의 총비용을 센다
“절반만 도니까 O(N²)의 절반이라 괜찮다”N(N−1)/2도 N²에 비례한다. 계수 1/2는 버려진다100억의 절반은 50억이고, 여전히 1억을 한참 넘는다
“평균적으로는 빠른 풀이예요”출제자는 최악의 입력을 일부러 넣는다먼저 최악의 경우를 확인하고, 평균·기대 시간 보장은 따로 구분한다 (2.4절)
“메모리는 넉넉하니 크게 잡자”지역 변수로 선언한 큰 배열은 스택이 좁아 바로 죽는다스택 한도를 확인하고 큰 고정 배열은 전역 또는 static으로 둔다 (4.3절)
“log N은 거의 1 아닌가”작지만 1은 아니다. N = 100만에서 20이고, N log N과 N은 20배 차이다아슬아슬한 문제에서는 log도 숫자를 대입해 계산한다
“복잡도만 맞추면 끝”같은 복잡도에서도 상수 차이로 갈린다복잡도를 맞춘 뒤에도 느리면 메모리 접근 순서를 의심한다 (2.5절)

자가 점검

  • log₂ 1,000 ≈ 10, log₂ 100,000 ≈ 17, log₂ 1,000,000 ≈ 20을 보지 않고 말할 수 있다
  • 빅오로 고칠 때 최고차항만 남기고 계수를 버리는 이유를 설명할 수 있다
  • 복잡도 7개를 빠른 순서대로 나열할 수 있다
  • N의 최댓값을 보고 유력한 복잡도 후보를 떠올릴 수 있다 (4.1절 표)
  • int 약 6,700만 개 · long long 약 3,300만 개라는 256MiB 이론상 최대치을 외웠다
  • 큰 지역 배열이 스택 한도를 넘을 수 있는 이유와 전역·static 대안을 설명할 수 있다
  • 연산 횟수 카운터를 처음부터 작성할 수 있다
