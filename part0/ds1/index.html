1왜 필요한가

같은 데이터라도 어떤 질문을 받느냐에 따라 담아야 할 그릇이 달라진다. 이 장은 그 사실을 몸으로 느끼는 데서 시작한다.

1.1 학생 10만 명의 성적표

전국 학생 10만 명의 성적이 있다고 하자. 데이터는 똑같은데, 세 가지 질문이 들어온다.

번호질문가장 단순한 방법10만 번 물어보면
①3번 학생의 점수는?학번을 인덱스로 쓴 배열 a[3]10만 번 → 즉시
②“김민수”의 점수는?처음부터 끝까지 이름 비교10만 × 10만 = 100억 번
③지금 1등은 누구?전체를 훑어 최댓값 찾기10만 × 10만 = 100억 번

연산 횟수와 실제 실행 시간은 다르다

학습용으로 단순 연산 약 1억 회 ≈ 1초라는 거친 기준을 쓰기도 하지만, 실제 속도는 컴퓨터·연산 종류·메모리 접근·컴파일러에 따라 크게 달라진다. 100억 회 수준의 반복은 1초 제한에서 매우 불리하다. ①은 직접 접근으로 유리하고, ②③은 같은 질문을 반복하면 비효율적이다. 데이터가 같아도 질문이 다르면 적합한 구조가 달라진다.

인덱스 주의: 여기서는 학번을 배열 인덱스로 직접 사용하여 3번 학생을 a[3]에 둔다. 1번부터 10만 번까지 쓰려면 C 배열의 길이는 최소 100,001이어야 한다.

②는 이름을 키로 쓰는 구조(해시 테이블, 21장)를 사용하면 평균적으로 O(1)에 찾는다. ③은 최댓값을 루트에 두는 최대 힙(18장)을 사용하면 최댓값 조회는 O(1), 최댓값 제거는 O(log N)에 수행할 수 있다. 이렇게 질문에 맞게 데이터를 담는 방식이 자료구조다.

1.2 자료구조를 고른다는 것

Q. 그럼 가장 빠른 자료구조 하나만 외우면 되지 않나요?
그런 것은 없다. 최대 힙은 최댓값을 바로 확인할 수 있지만 임의의 학번 검색에는 적합하지 않고, 일반 배열은 번호로 즉시 접근할 수 있지만 별도의 정렬·최댓값 관리가 없다면 최댓값을 찾으려고 전체를 살펴야 한다. 모든 연산에 언제나 최적인 단일 자료구조는 없다. 필요하면 두 구조를 함께 쓰기도 한다. 그래서 외우는 것이 아니라 고르는 것이다.

2개념과 그림

자료구조를 고르려면 먼저 “할 수 있는 일”과 “만드는 방법”을 분리해서 볼 줄 알아야 한다. 그 분리의 이름이 ADT다.

2.1 자판기로 이해하는 ADT

음료 자판기 앞에 섰다고 하자. 우리가 아는 것은 버튼뿐이다. “동전을 넣는다 / 버튼을 누른다 / 음료가 나온다 / 거스름돈을 받는다.” 내부에 음료가 어떻게 쌓여 있는지, 어떤 모터가 도는지는 모르고, 알 필요도 없다.

2.2 세 단어 정리

용어뜻자판기로 말하면
자료 (data)저장하려는 값 자체안에 들어 있는 음료
ADT
(추상 자료형)		무엇을 할 수 있는가의 목록. 연산의 이름·입력·출력·규칙만 정하고, 만드는 방법은 말하지 않는다버튼 배치와 사용 설명서
자료구조
(구현)		어떻게 만드는가. 실제 메모리에 값을 배치하고 연산을 코드로 작성한 결과내부 선반·모터·배선

한 문장으로

ADT는 약속이고, 자료구조는 그 약속을 지키는 물건이다. 약속 하나에 물건은 여러 개일 수 있다.

2.3 왜 굳이 나누어 생각하는가

  • 문제 풀이 순서가 분명해진다. 먼저 “어떤 연산이 필요한가(ADT)”를 정하고, 그다음 “그 연산을 가장 싸게 하는 방법(구현)”을 고른다. 거꾸로 하면 익숙한 배열부터 떠올리고 문제에 끼워 맞추게 된다.
  • 갈아 끼울 수 있다. 연산 이름이 같으면 속을 바꿔도 나머지 코드는 그대로다. 인터페이스와 동작 조건을 지킨다면 배열 스택을 연결 스택으로 바꾸어도 호출 코드를 유지할 수 있다. 단, 연결 스택도 메모리를 사용하며, 메모리 부족 자체를 자동으로 해결하지는 못한다.
  • 복잡도를 비교할 수 있다. 같은 약속을 지키는 두 물건의 비용을 표로 나란히 놓고 고를 수 있다(2.5절).

2.4 연산 명세표 — 이 장의 핵심 도구

ADT를 적는 공식 양식이 연산 명세표다. 아래 다섯 칸을 채운다.

칸이름적는 내용빠뜨리면 생기는 일
1연산연산의 이름 (동사로)무엇을 만드는지 흐려진다
2입력받는 값과 그 타입함수 모양이 안 정해진다
3출력돌려주는 값. 없으면 “없음”반환값을 쓰다 말다 한다
4사전조건이 연산을 부르기 전에 참이어야 할 조건빈 스택 pop처럼 잘못된 호출을 막기 어렵다
5결과연산이 끝난 뒤의 상태 변화무엇이 바뀌는지 모른 채 쓴다

작성 예 — 스택 ADT

스택은 “나중에 넣은 것이 먼저 나오는” 그릇이다. 쌓아 둔 접시 더미를 떠올리면 된다. 아래 명세는 최대 용량이 정해진 스택을 가정한다.

연산입력출력사전조건결과
push정수 x없음가득 차 있지 않을 것x가 맨 위에 놓인다. 크기 1 증가
pop없음정수비어 있지 않을 것맨 위 값이 빠져나온다. 크기 1 감소
top없음정수비어 있지 않을 것상태가 바뀌지 않는다 (들여다보기만)
empty없음참/거짓없음상태가 바뀌지 않는다

사전조건은 왜 따로 적는가

pop의 사전조건을 적어 두면 코드를 쓸 때 if (!empty()) pop();을 자동으로 떠올린다. 대회에서 틀리는 상당수가 빈 상태에서 꺼내려다 생긴 사고다.

명세를 C 선언으로 옮기면

입력·출력이 그대로 매개변수와 반환형이 된다. 만드는 방법은 한 글자도 쓰지 않았다.

/* stack.h — 스택 ADT의 약속만 적은 파일 (구현 없음) */
typedef struct Stack Stack;        /* 속은 숨긴다 */

Stack *stack_create(int cap);
void   stack_push (Stack *s, int x);   /* 사전: 가득 차지 않음 */
int    stack_pop  (Stack *s);          /* 사전: 비어 있지 않음 */
int    stack_top  (const Stack *s);    /* 상태 안 바뀜 → const */
int    stack_empty(const Stack *s);
void   stack_free (Stack *s);

이 파일은 구현을 감춘 함수 인터페이스 선언이다. 이 선언에 맞는 구현을 연결하면 호출하는 쪽은 내부 배열이나 연결 구조를 몰라도 스택을 사용할 수 있다. stack_create(cap)에는 양수 용량을 전달하고, 생성 실패나 메모리 부족을 처리하는 규칙은 실제 구현 시 정해야 한다. 실제 구현은 06장에서 작성한다.

2.5 같은 ADT, 서로 다른 구현

이번에는 “순서가 있는 값들의 목록”을 다루는 리스트 ADT를 보자. 연산은 네 가지로 정한다.

get(i) i번째 읽기 · insert(i,x) i번째에 끼워 넣기 · erase(i) i번째 빼기 · push_back(x) 맨 뒤에 붙이기. 인덱스는 0부터 시작한다. 이 약속은 배열로도 단일 연결 리스트로도 지킬 수 있다. 아래 O(1)은 표에 적은 별도 조건을 만족할 때의 비용이다.

연산배열 구현연결 구현왜 그런가
get(i)O(1)O(N)배열은 주소를 바로 계산, 연결은 i번 따라가야 함
insert(i, x)O(N)O(1)* / 위치 탐색 시 O(N)배열은 뒤를 밀고, 연결은 직전 노드를 안다면 포인터 연결만 고침
erase(i)O(N)O(1)* / 위치 탐색 시 O(N)배열은 뒤를 당기고, 단일 연결은 직전 노드를 안다면 연결을 고침
push_back(x)O(1)**O(1)***배열의 여유 공간, 연결 리스트의 꼬리 포인터가 중요

* 단일 연결 리스트에서 삽입·삭제 위치의 직전 노드(맨 앞은 머리 포인터)를 이미 아는 경우다. 인덱스 i만 주어지면 찾아가는 데 O(N)이 걸릴 수 있다. ** 배열은 충분한 용량이 있으면 O(1), 크기를 자동 확장하는 동적 배열은 평균이 아닌 분할 상환 O(1)이다. *** 연결 리스트는 꼬리 포인터를 유지해야 O(1)이다.

Q. 그러면 어느 쪽이 더 좋은 구현인가요?
올바른 질문은 “어떤 연산이 몇 번 불리고, 삽입 위치를 이미 알고 있는가”이다. 임의 인덱스 조회가 많으면 배열이 유리하고, 앞쪽 삽입이 많거나 직전 노드를 이미 아는 연산이 많으면 연결 리스트가 유리할 수 있다.

2.6 총비용 계산 — 고르는 방법

구현 선택은 곱셈과 덧셈이다. (1회 비용) × (호출 횟수)를 더해 대략 비교한다. N = 100,000인 경우로서, 아래는 각 연산의 최악 규모 O(1)≈1, O(N)≈10만을 단순화한 교육용 추정이다. 연결 리스트의 삽입은 항상 맨 앞 insert(0,x)이고, get(i)는 먼 위치까지 탐색할 수 있다고 가정한다.

상황배열 총비용연결 총비용선택
get 10만 번
맨 앞 insert 10번		10만×1 + 10×10만
= 110만		10만×10만 + 10×1
= 100억		배열
get 10번
맨 앞 insert 10만 번		10×1 + 10만×10만
= 100억		10×10만 + 10만×1
= 110만		연결

규모가 110만 대 100억처럼 크게 벌어지면 1초 제한에서 불리한 쪽을 피할 근거가 된다. 단, 빅오에서 실제 실행 초를 정확히 예측할 수는 없다. 자료구조를 고른다는 것은 호출 횟수와 필요한 연산의 비용을 함께 비교한다는 뜻이다. 복잡도 훈련은 다음 장(02 시간·공간 복잡도)에서 다룬다.

3연산 중심 사고 — 문제에서 명세 뽑아내기

이 장의 필수 과제는 코드가 아니라 명세표다. 문제를 읽고 명세표로 옮기는 3단계 절차를 익힌다.

3.1 3단계 절차

1단계 — 무엇을 담는가

저장할 값 한 개의 정체를 한 줄로 적는다. “정수 하나”인지 “(이름, 점수) 쌍”인지 “문자열”인지.

2단계 — 어떤 연산인가

문제의 동사에 밑줄을 긋는다. 넣는다·뺀다·찾는다·센다·가장 큰 것을 꺼낸다. 그 동사가 그대로 연산이 된다.

3단계 — 몇 번 부르는가

제약 조건에서 각 연산의 최대 호출 횟수를 적는다. 이 숫자가 구현을 고르는 근거가 된다.

3.2 적용 사례 — 괄호 검사

문제

길이 N(N ≤ 100,000)인 문자열이 주어진다. 소괄호 ( )만으로 이루어져 있다. 짝이 올바르게 맞는지 판정하라. 예를 들어 (())()는 올바르고 ())(는 올바르지 않다.

단계정리한 내용
1 담을 것아직 짝을 못 찾은 여는 괄호. 값은 사실상 “여는 괄호가 하나 있다”는 표시뿐이므로 정수 1개 또는 문자 1개
2 연산여는 괄호를 만나면 넣는다 / 닫는 괄호를 만나면 가장 최근 것을 뺀다 / 뺄 것이 있는지 묻는다 / 끝나고 남았는지 묻는다
3 횟수문자 하나당 최대 1회 → 넣기 최대 10만 번, 빼기 최대 10만 번, 묻기 최대 10만 번

“가장 최근에 넣은 것을 뺀다”가 핵심이다. 이 한 문장이 스택 ADT를 지목한다. 2.4절의 명세표가 그대로 쓰인다. 각 문자를 한 번 처리하면서 스택을 O(1)씩 조작하므로 전체 알고리즘은 O(N)이며, N = 10만인 경우 효율적으로 처리할 수 있다. 소괄호만 있다면 정수 카운터 하나로도 같은 판정을 할 수 있다.

순서를 지키자

초보자는 문제를 보자마자 “스택 써야지”로 간다. 맞을 때도 있지만, 틀리면 끝까지 틀린다. 동사를 먼저 뽑고 나서 그 동사 집합에 맞는 ADT를 고르는 순서를 지키면, 처음 보는 문제에서도 길이 보인다.

4복잡도 관점 미리 보기

02장에서 본격적으로 다루지만, 명세표를 쓸 때 함께 적어야 할 한 칸이 있다.

명세표에 “이 연산 1회의 비용” 칸을 하나 더 두면, 총비용을 거칠게 계산할 수 있다. 배열 스택과 연결 스택은 주요 연산의 빅오 시간복잡도는 같지만, 메모리 할당 여부 등 실제 상수 비용은 다르다.

연산배열 스택 1회연결 스택 1회10만 번 부르면
pushO(1)O(1) + 메모리 할당둘 다 10만 번 수준 — 통과
popO(1)O(1) + 메모리 해제둘 다 통과하나 배열이 상수가 작다
top / emptyO(1)O(1)차이 없음

스택처럼 끝에서만 넣고 빼는 경우에는 두 구현의 주요 연산이 O(1)이다. 크기 한도를 알 수 있고 메모리가 충분하면 상수 비용이 작고 구현이 단순한 배열이 유리하다. 반대로 리스트에서 중간 삽입·삭제의 직전 노드를 이미 아는 경우는 연결 리스트의 O(1) 장점이 생긴다. 인덱스만 주어져 탐색이 필요하다면 둘 다 O(N)일 수 있다.

예제 1 명세표 작성

큐 ADT의 연산 명세표를 작성하라. 연산은 enqueue(뒤에 넣기), dequeue(앞에서 빼기), front(앞을 보기), empty 네 가지다.

풀이. 스택 명세표와 양식은 같고, “맨 위” 대신 “맨 앞/맨 뒤”가 들어간다. 사전조건을 빠뜨리지 않는 것이 핵심이다.

예제 2 ADT 고르기

은행 창구에 손님이 도착한 순서대로 번호표를 받고, 창구가 비면 가장 오래 기다린 손님을 부른다. 필요한 ADT는 무엇이며, 그렇게 판단한 근거가 되는 동사는 무엇인가?

풀이. 동사는 “도착한 순서대로 넣는다”와 “가장 오래 기다린 사람을 뺀다”이다. 먼저 들어온 것이 먼저 나오므로 큐다. 만약 “VIP 손님을 먼저 부른다”가 추가되면 동사가 “우선순위가 가장 높은 사람을 뺀다”로 바뀌고, 그 순간 ADT는 우선순위 큐(18장)로 교체된다. 조건 한 줄이 바뀌면 ADT가 바뀐다.

예제 3 구현 고르기

리스트 ADT를 쓰는 두 프로그램이 있다. N = 100,000일 때 각각 어떤 구현이 유리한지 총비용을 계산해 판단하라. 배열은 충분한 용량이 있고, 연결 리스트는 꼬리 포인터를 유지한다고 가정한다.

  • 프로그램 A — push_back 10만 번 후, 여러 인덱스에 get(i)를 독립적으로 10만 번 요청 (연결 리스트의 순차 순회로 대체 불가)
  • 프로그램 B — 맨 앞에 insert(0, x) 10만 번 후, 처음부터 끝까지 한 번 순회하며 출력

풀이. 연산별 비용표(2.5절)를 보고 곱해서 더한다. 값은 연산 1회당 최대 N에 비례하는 단순 비용 모델로 계산한 대략적인 규모이다.

배열 구현연결 구현판단
프로그램 A10만×1 + 10만×1 = 20만10만×1 + 10만×10만 = 100억배열
프로그램 B10만×10만 = 100억10만×1 + 10만 = 20만연결

B에서 배열이 느린 이유는 맨 앞 삽입마다 기존 원소를 전부 한 칸씩 밀기 때문이다. 다만 B는 “앞에 쌓고 앞에서 읽는다”이므로 뒤에 쌓고 거꾸로 읽는 방식으로 문제 자체를 뒤집으면 배열로도 20만 번에 끝난다. 구현을 바꾸는 것 말고, 연산을 바꾸는 길도 있다는 점을 기억하자.

예제 4 잘못된 명세 고치기

다음은 어떤 학생이 작성한 스택 명세표의 일부다. 잘못된 곳을 네 군데 찾아 고쳐라.

연산입력출력사전조건결과
pop정수 x없음없음맨 위 값이 빠진다
top없음정수비어 있지 않을 것맨 위 값이 빠진다

풀이. 네 칸에 오류가 있다.

  • pop의 입력 — pop은 받을 값이 없다. 무엇을 뺄지는 스택이 스스로 안다. 입력은 “없음”.
  • pop의 출력 — 뺀 값을 돌려주어야 하므로 출력은 “정수”.
  • pop의 사전조건 — 비어 있지 않을 것이라는 조건이 빠졌다. 이를 확인하지 않으면 빈 스택에서 꺼내는 잘못된 호출이 발생할 수 있다.
  • top의 결과 — top은 들여다보기만 한다. “맨 위 값이 빠진다”가 아니라 “상태 변화 없음”이어야 한다. 이 혼동은 실제로 top을 부르고 값이 사라져 버리는 버그로 이어진다.

예제를 풀고 나서 — 반복해서 나오는 세 가지

  • 꺼내는 연산은 출력이 있다. 보는 연산은 상태를 바꾸지 않는다.
  • 꺼내거나 보는 연산에는 거의 항상 “비어 있지 않을 것”이 붙는다.
  • 구현 선택은 느낌이 아니라 (비용 × 횟수)의 덧셈으로 결정한다.

6연습 문제

코드를 쓰는 문제는 없다. 모두 공책에 표와 문장으로 답한다. 권장 시간 40분.

01덱 ADT 명세표를 작성하라. 연산은 push_front, push_back, pop_front, pop_back, empty 다섯 가지다. 다섯 칸을 모두 채울 것.
02다음 서술이 ADT에 속하는 내용인지 구현에 속하는 내용인지 분류하라.
① pop은 비어 있을 때 부르면 안 된다   ② 값들을 배열에 연속으로 저장한다   ③ push는 값을 하나 받고 아무것도 돌려주지 않는다   ④ 용량이 모자라면 두 배로 늘린다   ⑤ 나중에 넣은 값이 먼저 나온다   ⑥ 각 노드는 다음 노드의 주소를 들고 있다   ⑦ size는 현재 원소 개수를 돌려준다   ⑧ 맨 위 위치를 정수 변수 하나로 기억한다
03“가장 작은 값을 꺼낸다”라는 연산이 필요한 현실 상황 세 가지를 서로 다른 분야에서 들고, 각각 무엇이 ‘값’이고 무엇이 ‘작다’의 기준인지 한 줄씩 쓰라.
04배열로 구현한 리스트에서 insert(0, x)가 O(N)인 이유를, N = 5인 구체적 예를 그려 가며 설명하라. 몇 번의 이동이 일어나는지 숫자로 밝힐 것.
05영어 단어와 뜻을 저장하고 단어로 뜻을 찾는 사전 ADT의 명세표를 작성하라. 연산은 최소 insert, find, erase 세 가지를 포함할 것. ‘담는 값’이 정수가 아니라는 점에 주의하라.
06음악 재생목록 프로그램을 만든다고 하자. “다음 곡 재생 / 이전 곡으로 / 목록 맨 뒤에 곡 추가 / 현재 곡 삭제 / 목록 길이 확인”이 필요하다. 3.1절의 3단계 절차에 따라 ① 담을 것 ② 연산 목록 ③ 각 연산의 예상 호출 횟수를 정리하라.
07아래 표의 빈칸을 채워라. 리스트 ADT를 배열과 연결 리스트로 구현했을 때의 1회 비용이다.

조건: insert(i,x)에는 인덱스 i만 주어지고 직전 노드 탐색이 필요하며, 배열에는 여유 공간이 있고 연결 리스트는 꼬리 포인터를 유지한다.

7도전 문제

다음 장 이후의 내용과 이어지는 문항이다. 답이 하나로 정해지지 않을 수 있으니, 근거를 갖춘 설계를 쓰는 것이 목표다.

C1양 끝과 가운데
다음 네 연산을 모두 지원하는 ADT를 설계하라. ① 맨 앞에 넣기 ② 맨 뒤에 넣기 ③ 현재 들어 있는 값들 중 가장 작은 값 꺼내기 ④ 맨 앞 값 확인하기(삭제하지 않음).
(1) 다섯 칸 명세표를 작성하라.
(2) 정렬하지 않은 배열 하나로 순서를 유지하고, 매번 선형 탐색으로 최솟값을 찾는다면 ③의 1회 비용은 얼마인가? N이 10만일 때 ③을 최대 10만 번 부르면 총 몇 번 규모인가?
(3) 위의 단순 구현이 왜 비효율적인지 설명하고, 앞뒤 순서 정보와 최솟값 정보를 함께 관리할 수 있는 구조의 성질을 말로 기술하라. (최솟값 관리는 18장의 힙과 연결된다.)
C2실행 취소와 다시 실행
그림판 프로그램에 ‘되돌리기(undo)’와 ‘다시 실행(redo)’을 붙이려 한다. 사용자가 새 그림을 그리면 redo로 돌아갈 수 있었던 기록은 모두 사라진다.
(1) 이 동작을 구현하려면 ADT 두 개가 필요하다. 각각 무엇이며 왜 그런지 동사를 근거로 설명하라.
(2) “새 그림을 그리면 redo 기록이 사라진다”는 규칙은 명세표의 다섯 칸 중 어느 칸에 적어야 하는가?
(3) 되돌리기 기록을 최근 100개까지만 보관하려 한다. 어떤 연산이 추가로 필요한지 쓰고, 그 연산 때문에 ADT 선택이 달라지는지 논하라.

8막히는 지점

흔한 생각무엇이 틀렸나바로잡기
“ADT와 자료구조는 같은 말 아닌가”ADT는 약속, 자료구조는 그 약속을 지키는 물건이다. 하나의 약속에 물건은 여럿스택 ADT 하나에 배열 스택·연결 스택 두 구현이 있다는 사실을 예로 떠올린다
“문제 보면 바로 자료구조가 떠올라야 한다”떠오른 것이 틀리면 끝까지 틀린다. 숙련자도 동사부터 뽑는다3.1절의 3단계를 공책에 적고 시작한다. 20초면 끝난다
“사전조건은 당연한 거라 안 적어도 된다”안 적으면 코드에서도 안 지킨다. 빈 스택 pop은 가장 흔한 런타임 오류꺼내기·보기 연산을 적을 때마다 “비었으면?”을 소리 내어 묻는다
“배열이 제일 빠르니까 다 배열로”배열은 i번째 읽기만 빠르다. 중간 삽입·삭제는 O(N)2.5절 표를 보고 어떤 연산이 몇 번 불리는지 곱셈해 본다
“top과 pop은 비슷한 거니까”top은 상태를 안 바꾸고 pop은 바꾼다. 섞어 쓰면 값이 사라지거나 두 번 처리된다명세표의 ‘결과’ 칸을 확인하는 습관을 들인다

자가 점검

  • ADT와 자료구조의 차이를 자판기 비유 없이 내 말로 설명할 수 있다
  • 다섯 칸(연산·입력·출력·사전조건·결과)을 보지 않고 떠올릴 수 있다
  • 스택과 큐의 명세표를 10분 안에 작성할 수 있다
  • 리스트 ADT에서 배열 구현과 연결 구현의 비용 차이를 표로 그릴 수 있다

  • “1초에 약 1억 번”이라는 거친 가정으로 연산 규모를 비교하되, 실제 시간을 단정하지 않는다

다음 장 예고 — 02 시간·공간 복잡도

이 장에서 “10만 × 10만 = 100억”처럼 손으로 비교한 연산의 증가 규모를 빅오 표기라는 공통 언어로 정리한다. N을 대입해 연산량의 대략적인 규모를 비교하고, 제약 조건을 바탕으로 알맞은 복잡도를 판단하는 훈련을 한다. 빅오만으로 정확한 실행 초를 계산할 수는 없다.
